# Hero swipes and brush interactions

The hero's three portraits now accept horizontal swipes and mouse/pen drags in both directions. The sequence wraps from 3 back to 1, and from 1 back to 3. Number buttons and keyboard arrows remain available. A focused portrait also accepts arrow keys. The selected number, image, caption, saved-look key and screen-reader status stay together. Vertical gestures remain available for page scrolling; small taps, cancelled gestures and touches on the numbered/save buttons do not select another portrait. Older browsers without Pointer Events use Touch Events. Reduced-motion preferences suppress the drag animation while preserving selection.

The reported mobile brush issue had a visible cause: CSS hid the brush graphic in touch layouts, even while brushing was active. Start also initiated smooth scrolling while the finger interaction was being armed. Touch activation now reveals and positions the brush immediately without initiating a scroll. The first contact positions the brush and reveals colour; subsequent movement follows the finger. Active painting uses `touch-action:none` on the portrait/canvas, and Done restores the scrolling surface and floating controls. Pointer-capture failures no longer abort the first mark. A Touch Events fallback supports older browsers, with cancellation and secondary-finger handling. Existing normalized stroke replay, reset, full reveal and slider modes are retained.

The website and Academy use a native 32×32 rose-and-gold brush cursor on devices advertising a fine pointer and hover. The SVG has an explicit size, with a matching PNG fallback and normal cursor keywords. Text fields retain their text cursor, ranges retain resizing affordances, and disabled controls retain their disabled cursor. The studio uses its larger brush illustration while drawing. Browser-controlled chrome, scrollbars and phone touch input cannot be changed into a native website cursor. Unsupported browsers, including iPadOS configurations that restrict custom cursors, retain their normal pointer.

## Verification

`node --test tests/*.test.mjs` covers all 35 cases: hero gesture directions and wraparound, vertical scrolling intent, small taps, button interactions, pointer cancellation, capture failure, quick flicks with coalesced moves, legacy touch streams, the visible Start state, capture errors in painting, touch cancellation and secondary fingers, plus the existing brush, Academy and Instagram cases.

Browser checks at 320, 390, 768 and 1440 pixels in both themes found no document overflow or clipped swipe hints. Number buttons and keyboard arrows cycled 1→2→3→1 and 1→3, keeping captions and save keys aligned. In the phone-sized preview, Start visibly displayed the brush and a real canvas click revealed a coloured area; Done hid it and restored `pan-y pinch-zoom` with an inactive canvas. Text fields retained `cursor:text`, and the computed page cursor referenced the local SVG/PNG. A native Chrome drag check was interrupted by the user controlling the window, so it was not counted as passed. Physical iOS/Android hardware was unavailable: touch gesture streams are regression-tested, while actual phone hardware remains a verification limit.
